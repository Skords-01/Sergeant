# Research pipeline for Sergeant

Turn one-off "open 10 tabs, take notes somewhere" research into a repeatable pipeline that fans out across sources, offloads the heavy analysis to a research harness, and **saves the result as a durable markdown artifact in the repo** so the next session builds on it instead of starting from zero.

This is the Sergeant-native adaptation of the popular "Claude Code + NotebookLM + Obsidian" research workflow. The external stack does **not** port literally (see § What does NOT port) — this skill maps each layer onto a primitive that already lives in this repo or this harness.

## Layer mapping (do not reinvent the external stack)

| Workflow layer | External tool | Sergeant-native primitive |
| -------------- | ------------- | ------------------------- |
| Execution / orchestration | Claude Code | this harness — you are it |
| Analysis offload | NotebookLM | the platform `deep-research` skill (fan-out search → adversarial verify → cited synthesis); plain `WebSearch` + `WebFetch` for a single shallow pass |
| Repo-context source | (n/a) | `pnpm agent:find "<query>"` over the monorepo + ADRs in `docs/04-governance/adr/` + planning docs in `docs/90-work/planning/` |
| Memory layer | Obsidian vault | `docs/90-work/research/` markdown artifacts + maintainer preferences already encoded in `docs/00-start/agents/decisions.md` |
| Preferences config | `claude.md` | `CLAUDE.md` / `AGENTS.md` / `decisions.md` — already the single source of truth |

## Pipeline

1. **Frame the question.** One sentence: what decision does this research unblock? If the prompt is vague ("research AI agents"), narrow it with the requester before fanning out — scope, region, time window, the specific call to be made.
2. **Pick the analysis engine.** Multi-source, fact-checked, or decision-grade → invoke the platform `deep-research` skill. A quick fact or single-source lookup → `WebSearch` / `WebFetch` directly; do not over-orchestrate a one-liner.
3. **Pull repo context when the question touches Sergeant.** Run `pnpm agent:find "<query>"` and read the ranked `file:line` pointers before claiming the repo does or does not do something. External claims and repo reality are separate sources — keep them separate in the writeup.
4. **Save the artifact (the memory layer is the point).** Write the synthesis to `docs/90-work/research/<YYYY-MM-DD>-<slug>.md`. Without this step the research evaporates and the next session repeats it. The artifact is the deliverable, the chat summary is a courtesy copy.
5. **Surface it in chat too** — a short synthesis plus the artifact path, so the requester can act without opening the file.

## Artifact format

Every file under `docs/90-work/research/` MUST carry the lifecycle header (Hard Rule #10) and be written in Ukrainian for prose (Hard Rule #15 — internal docs are UA):

```markdown
# <Тема дослідження>

> **Last validated:** <YYYY-MM-DD> by @<handle>. **Next review:** <YYYY-MM-DD>.
> **Status:** Active

## Питання
<що саме розблоковує це дослідження>

## Висновок
<2-4 речення: головна відповідь>

## Деталі
<структуровані знахідки, кожна з джерелом>

## Джерела
- <url / file:line> — <що звідси взято>

## Невідоме / наступні кроки
<де впевненість низька, що перевірити далі>
```

Cite every non-obvious claim. Mark low-confidence findings as low-confidence — a confident-but-wrong artifact poisons every session that reads it later.

## What does NOT port (and why)

- **NotebookLM / `notebooklm-py`** — no public API; requires an interactive Google browser login that does not exist in headless/CI sessions. `deep-research` fills the "offload heavy analysis" role without auth. Do not add `notebooklm-py` as a dependency.
- **yt-dlp / YouTube search** — YouTube is not a meaningful source for a product monorepo, and scraping pulls in a tooling + ToS surface this repo does not want. Use web sources, ADRs, and `agent:find` instead.
- **`/skill-creator` plugin** — repo skills are authored through `sergeant-writing-skills` (TDD-for-skills + `pnpm skills:lock`), not generated by a plugin. `skill-creator` is already retired on the repo surface (see the catalog's Deprecated table).
- **A separate Obsidian vault** — the repo `docs/` tree already *is* the versioned knowledge base; do not mirror artifacts into an external vault.

## Red flags

- "I'll just summarize from memory" → research means consulting sources; never answer a research prompt from training-data recall alone.
- "I'll keep the findings in the chat" → no artifact = no memory layer = you rebuilt nothing. Always write to `docs/90-work/research/`.
- "I'll port the YouTube/NotebookLM steps verbatim" → those layers do not run here; use the mapped primitive.
- "External blog says Sergeant does X" → verify against the repo with `pnpm agent:find` before recording it as fact.
- "Skip the lifecycle header, it's just a note" → Rule #10 applies to every file; the freshness linters will reject it.
